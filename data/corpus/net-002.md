# Private hostnames do not resolve from a worker

Applies when a worker can reach an IP address on a peered network but `NXDOMAIN` is
returned for the corresponding private hostname.

## Cause

Private DNS resolution requires the private network to have a DNS forwarding rule for
the customer domain. Network peering and DNS forwarding are configured separately, so
peering can be healthy while resolution fails.

## Resolution

1. Confirm peering state with `get_status` on the environment. `network.peering` must
   read `active`.
2. List forwarding rules in the console under **Private Network > DNS**. The customer
   domain suffix must appear with at least one reachable resolver IP.
3. If the rule is missing, add it. Propagation takes up to 10 minutes.
4. Restart the worker only after propagation completes. Restarting earlier will
   re-cache the failed resolution and appear to make the problem permanent.

## Escalate when

- `network.peering` reads `degraded` for more than 15 minutes.
- Forwarding rules are present and correct but resolution still fails from more than
  one environment, which indicates a resolver-side outage.
