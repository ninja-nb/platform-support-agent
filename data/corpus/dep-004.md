# Deploy starts but fails its health check

The worker reaches `STARTED` and then transitions to `DEPLOY_FAILED`. The event log
shows `HEALTH_CHECK_TIMEOUT` after the configured grace period.

## Cause

Three causes account for nearly all occurrences:

1. The application takes longer to become ready than the health-check grace period
   allows. The default grace period is 120 seconds.
2. The health-check path returns a non-2xx status, commonly because the path requires
   authentication.
3. The application binds to `127.0.0.1` rather than `0.0.0.0`, so the probe cannot
   reach it from outside the container.

## Resolution

1. Retrieve the worker startup log and find the last line before the probe failure.
2. If the application logged "ready" after the grace period, raise the grace period to
   exceed observed startup time.
3. If the probe received 401 or 403, point the health check at an unauthenticated
   path such as `/healthz`.
4. If nothing was logged at all, check the bind address.

## Escalate when

The startup log shows the application ready within the grace period and the probe
still timed out. That indicates a platform networking fault rather than a
configuration problem, and needs the Runtime team.
