# Deploy fails with INSUFFICIENT_CAPACITY

The deploy is rejected before any worker starts and the event log shows
`INSUFFICIENT_CAPACITY` with a region and instance class.

## Cause

The requested worker class has no available capacity in the target region. This is a
scheduling outcome, not a quota rejection. Quota rejections report
`QUOTA_EXCEEDED` instead and are covered by `quota-006`.

## Resolution

1. Read the region and worker class from the deploy event.
2. Retry in a different availability zone within the same region. Most capacity
   shortfalls are zone-local and clear within minutes.
3. If the workload tolerates it, drop to a smaller worker class. A `standard-4` deploy
   will frequently succeed where `standard-16` will not.
4. For a production rollout that cannot wait, request a capacity reservation. Lead
   time is two business days.

## Do not

Do not restart the existing service to "clear" the failure. The previous version is
still serving traffic and a restart drops it while no replacement capacity exists.

## Escalate when

`INSUFFICIENT_CAPACITY` persists in every zone of a region for more than 30 minutes.
